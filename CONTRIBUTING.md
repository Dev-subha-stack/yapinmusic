# Contributing

1. Create a feature branch; avoid committing directly to `main`.
2. Keep UI, game rules, catalog data, and persistence concerns separated.
3. Run `npm test`, `npm run check`, and `npm run build` before opening a pull request.
4. Add or update tests for changes to shared game logic.
5. Never commit credentials, private player data, or Supabase service-role keys.
6. Describe visible UI changes and include screenshots for layout changes.
